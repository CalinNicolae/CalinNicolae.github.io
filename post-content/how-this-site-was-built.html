The decision to build from scratch

When it came time to put together a portfolio for the Professional Networking module at Howest, the obvious shortcut would have been WordPress, Wix, or a pre-built GitHub Pages theme. I chose not to go that route. For a cybersecurity and computer science student, handing control of your public presence to a third-party feels like a contradiction. More practically, a hand-built site demonstrates exactly the kind of skills that make this portfolio worth looking at. I also consider it a great practicing opportunity for my coding skills.

This post documents how the site was built, how it works, and how to add new content to it.

The stack

The entire site runs on three technologies:

  • HTML
  • CSS
  • JavaScript

How the design system works

Every color, spacing value, and font is defined as a custom CSS property. Changing something, for example the primary neon accent from cyan to any other color means only one edit in only one place. Utility classes are defined once and reused across pages.

How the blog system works

The blog is driven by a single JSON file data/posts.json which acts as the data layer. Each entry holds the post's metadata: title, date, category, tags, excerpt, cover image path, and a pointer to the content file.

Each blog post's content lives in post-content/ as a small HTML fragment. When you navigate to post.html?id=how-this-site-was-built, the page reads the URL parameter, fetches the matching entry from posts.json, renders all the metadata into the header, then fetches post-content/how-this-site-was-built.html and injects it into the article body. No server, no database, just fetch().

Adding a new post

Four steps:

  1. Add a new JSON object to data/posts.json with all required fields.
  2. Create post-content/your-slug.html with the article body HTML.
  3. Drop any images into assets/images/ and update the paths in the JSON entry.
  4. Push to the main branch and GitHub Pages deploys automatically within seconds.

Tools and workflow

This website was built using Visual Studio Code, Git for version control, and browser developer tools for layout work. Claude Code and other AI tools were used as a research and brainstorming aid throughout: to look up CSS behaviour, explore approaches to the dynamic post loading, and reason through animation logic. Every line in this repository was read, reasoned about, and deliberately placed.

Hosting

This website is hosted on GitHub Pages, because it's free, reliable, and it stays live after graduation. A .nojekyll file in the repository root tells GitHub Pages to skip the Jekyll build and serve the files directly. The result is a fast, dependency-free static site with no ongoing cost.
